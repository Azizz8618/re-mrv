## Fortran-часть DEB (стр.281–291) — результат расшифровки

Исходник: `docs/deb/deb_fortran_src.txt` (654 строки, из них 638 — тело
Fortran-программы; 518 операторов эталонного листинга DEB00080..DEB07060,
477 скомпилированных операторов). Обёртка: `build/deb/deb_fortran.b6`,
полный листинг: `build/deb/deb_fortran.lst`.

Команда сборки (из каталога с доступными дисками dispak):

```bash
cd /home/azizz/Yandex.Disk/re-mrv
python3 - <<'PY'
src='docs/deb/deb_fortran_src.txt'
lines=open(src,encoding='utf-8').read().splitlines()
i=0
while i<len(lines) and lines[i].lstrip().startswith('C'): i+=1
header=['шифр 419999 зс5^','лен 41(2048)^','eeв1а3','*name DEB',
        '*no list','*full list','*system']
footer=['*execute','*end file','``````','еконец']
open('build/deb/deb_fortran.b6','w',encoding='utf-8').write(
    '\n'.join(header+lines[i:]+footer)+'\n')
PY
(cd build/deb && timeout 60 dispak deb_fortran.b6 > deb_fortran.lst 2>&1)
grep 'ЧИСЛО ОШИБ' build/deb/deb_fortran.lst
# -> ЧИСЛО ПЕРФ. 4465  ЧИСЛО ОШИБ. ОПЕРАТОРОВ  0000
```

**Компиляция:** `0 ошибок`. В сгенерированном МАДЛЕН-коде присутствуют
все четыре входа: `SPIGUN : ,NAME,`, `DEWR : ,ENTRY,`,
`PZAVAR : ,ENTRY,`, `DERD : ,ENTRY,`. Список внешних ссылок совпадает
с таблицей `EXTERNALS` эталонного листинга (стр.293):
`VTWORK`, `CLOPEN`, `VTWRIT`, `VTREAD`, `VTSTAT`, `IOCTTI`, `GIVRGS`,
`DRIN`, `GIVRGM`, `OKNO`, `VTDESH`, `GSTISO`, `VTK`, `VTN`, `VTN16`,
`VTNRL`, `VTI`, `VTB`, `RDPTK`, `RDPTN`, `DESR`, `WRDESK`, `USM35`,
`IOCTM`, `RDM35`, `MEM`, `FINAL`, `ISOCOD`, `WRPTN`, `TODE`, `SHISO`,
`GOTO`, `CALL`, `VTINVI`.

**Имя `RZAVAR`:** в эталонном листинге (стр.282, `TABLE OF ENTRIES` стр.293)
записано `ENTRY PZAVAR` / `PZAVAR >00071<`. `RZAVAR` в статусных таблицах —
ошибочная гипотеза OCR; в исходниках DOG такой символ не встречается.
Для замыкания DOG достаточно `SPIGUN` и `DERD` (см. `docs/dog_all.txt`,
`CALL,SPIGUN`; `CALL DERD` на стр.44).

### правки для компиляции (все — в исходнике, помечены в шапке)

| Скан | В исходнике | Причина |
|---|---|---|
| цифры `1,2,…,0` перед строками `DATA` | удалены | это номера перфокарт (кол.73–80), не часть оператора |
| `6HПС 1`, `6HYES`, `6H      ` | `'ПС1   '`, `'YES   '`, `'      '` | эмуляторный компилятор теряет `)` при концевых/внутренних пробелах в 6H |
| `RD PT K`, `RD PT N` | `RDPTK`, `RDPTN` | идентификатор >6 символов (`СЛИШКОМ МНОГО СИМВОЛОВ`) |
| `NA=MFLD(1).OR.0` | `NA=MFLD(1)` | `.OR.` не допускается в арифметическом присваивании; `OR 0` — холостая операция |
| `TLINE` не описан | `INTEGER TLINE` | в скане описания нет; вероятно, в неперенесённом COMMON |
| пропущен блок `15000` | восстановлен по стр.290 | вcomputed GOTO есть метка 15000 |
| `FORMAT 105/331` | два FORMAT с одинаковым текстом | в скане разметка неоднозначна;нужны для `ENCODE(...,105,...)` и `ENCODE(...,331,...)` |
| `IF(ALL(LCD(4).EQ.0)GOTO 101` | пропущено | неразборчиво; на следующую строку `IF(IDCBT(4).EQ.0)GOTO 101` |
| тексты FORMAT (110, 105, 321, 343 и др.) | частично уточнены по изображению | OCR дал только обрывки; помечено `C?` |

Эталонный листинг завершается `ERRORS: 0, WARNINGS: 1 (WARN 001 IN 0518
THERE IS NO PATH TO THIS STATEMENT)` — предупреждение о недостижимой ветви,
не ошибка. Наша сборка тоже даёт 0 ошибок.

## Формат транскрипции

Левая колонка листинга — **восьмеричные адреса**, вторая колонка —
`А ИСП` (для нашего исходника не нужна), `DEBxxxxx` — генераторские
номера строк листинга (в исходник не включены). Метки МАДЛЕН в исходнике
имеют ведущий пробел (иначе `ОТСУТСТВУЕТ ЗАГОЛОВОК ПОДПРОГРАММЫ`).

## Правки, сделанные для компиляции (зафиксированы)

| Оригинал скана | В исходнике | Причина |
|---|---|---|
| `AFX` | `AEX` |неверная мнемоника (`ОШИБКА В КОП`) |
| `ITC` | `ITS` | `ОШИБКА В КОП` |
| `SH DS` | `SH PS` | неописанный идентификатор |
| `RD`, `A` (внешние) | добавлены `BSS` | неописанный идентификатор |
| константы `6H'7''7'...`, `6H'0''7'...` | `=6H777777`, `=6H077777` | кавычки междуdigit'ами не принимаются ассемблером; сохранена последовательность цифр |
| `, CONT,6H00 ...` (TABKOP и таблица стр.335) | `, GOST,6H00 ...` | в эмуляторном ассемблере `CONT` не принимает 6H-литерал; `GOST` — штатный способ (~`TEXT55 : , GOST,6HТЕКСТ` в `dog2_compilable.txt`) |
| `: , BASE,*` (BASOR) | комментарий | директива не поддерживается эмуляторным ассемблером |
| модификаторы 21/23/25 (из колонки `А ИСП`) | удалены | это не модификаторы, а исполнительные адреса; >15 → `ОШИБКА В МОДИФИКАТОРЕ` |
| `STR` p.313 `, ПЗ ,UJ,` | комментарий | в эталонном листинге `НЕДОПУСТИМЫЙ ОПЕРАТОР`, `ЧИСЛО ОШИБ. ОПЕРАТОРОВ 0001` |
| `ZOO` (GOTO) | `BSS` | `ОШИБКА В КОП` |

## Пропуски (честно)

* **Стр.281–291** — Fortran-программа целиком расшифрована и компилируется.
  **Стр.294–301** — отдельные Fortran-подпрограммы (`VIN`, `VIN16`, `VINRL`,
  `VTKOM`, `VTIS`, `VTB`, `WRDESK`) не расшифрованы; они не нужны для
  замыкания внешних ссылок DOG. Стр.292–293 — выходные таблицы компилятора
  (адреса операторов, `EXTERNALS`, `ENTRIES`, `COMMON BLOCKS`), стр.302 —
  завершающая карта `*ASSEMBLER`.
* **Стр.311–312, 316, 318, 319–322, 327–329, 333–334** — не транскрибированы:
  `ISO COD`, продолжение `GOTO`/`RD PT N`, `DES R`, хвост `TABKOP` и
  таблиц текстов. Их absence не мешает компиляции включённых подпрограмм,
  но модуль DEB Reconstruction **неполон**.

## Эталонная таблица ссылок (стр.335)

Точная копия из скана (адреса восьмеричные) приведена в комментариях
в начале `deb_src.txt`. Ответственность за соответствие: адреса сканных
подпрограмм (например `INFW 00023`, `RET 00007` на p.303; `INFWR 00020`,
`LPDEB1 00007`, `RETURN 00014` на p.323; `TABKOP 00056` на p.329)
перенесены в комментарии. Прямая поразрядная сверка с object-кодом
не проводилась — эмуляторный ассемблер расставляет адреса по-своему
(каждая подпрограмма компилируется с базы 0), поэтому совпадение
абсолютных адресов с эталоном не ожидается.
