# Блок МРВ с базой 04000(8): что удалось сделать на самом деле

Дата: 18.11.2026. Исполнитель: сабагент.
Рабочая область: `/tmp/.private/azizz/opencode/glissada/base4000/`.
Реальные образы дисков не изменялись: все прогоны — с `BESM6_PATH`,
указывающим на temp-копии. Контроль: md5 реальных `2348` до/после —
`baa55e8e…` (Рабочий стол) и `f7425f17…` (`~/.besm6`), без изменений.

## 1. Краткий ответ

1. **Рабочий способ есть**: весь блок МРВ (50 модулей МАДЛЕН) компилируется
   `dispak` + `*assembler` заданием с `*to perso:404000`. PERSO-библиотека
   (каталог + тела 50 модулей) записывается на том 2348 **с базы 04000(8)**
   и занимает 13 зон `04000–04012₈`. Бинарный образ получен:
   `/tmp/.private/azizz/opencode/glissada/base4000/mrv_BASE4000.bin`
   (79 872 байта = 13 × 6144, md5 `73be8de03d7349851e15b30d661c6d68`).

2. **База 04000(8) как адрес загрузки в памяти МРВ-модулям через dispak
   не задаётся.** Это подтверждено опытами §4. Единственный механизм
   всей цепочки, который действительно задаёт адрес загрузки, — `наз <адрес>`
   линковщика РВС (или `НАЗ`/`СТАРТ` в МАКРО-БЕМШ-колоде); он работает с
   объектами МАКРО-БЕМШ (показано на модуле `consul` с `наз 04000`), но
   МАДЛЕН-объекты РВС не принимает (§5).

3. Поэтому, если под «базой 04000(8)» имеется в виду **адрес в памяти**,
   готового рабочего рецепта нет: нужен либо МАКРО-БЕМШ-исходник МРВ
   (его в проекте нет), либо конвертер МАДЛЕН→БЕМШ с сохранением
   релокаций, либо доработка РВС/загрузчика под формат МАДЛЕН-объекта.

Исходник: `src/integration/mrv_all.txt`, 8281 строка, 50 модулей.

Команды (только temp!):

## 3. Бинарный образ и запись на диск

Получение образа (повреждений не наносит):

```bash
BESM6_PATH=$PWD/tdisks besmtool dump 2348 \
    --start=04000 --length=13 --to-file=mrv_BASE4000.bin
python3 verify_image.py mrv_BASE4000.bin
```

`besmtool dump` пишет по 6144 байта на зону (только данные, без
контрольных слов), `besmtool write` читает тот же формат — round-trip
проверен: слова зон совпадают слово-в-слово, отличаются лишь служебные
слова/контрольные суммы зон (это нормально).

Запись **только на рабочую копию**:

```bash
cp /usr/local/share/besm6/2348 /path/to/WORKCOPY/2348
BESM6_PATH=/path/to/WORKCOPY besmtool write 2348 \
    --start=04000 --length=13 --from-file=mrv_BASE4000.bin
```

Внимание: `--start` у `besmtool` — **десятичное** число, если нет
ведущего `0`. `04000` в команде выше читается как восьмеричное = 2048₈.
Для `besmtool view` зона `4000₈` тоже задаётся как `04000`.

## 4. Опыты: база как адрес загрузки НЕ задаётся

Все опыты — на temp-копиях, минимальный модуль `TINYM` и полный МРВ.

| Опыт | Воздействие | Результат (дословно) |
|------|-------------|----------------------|
| A |Добавлена строка паспорта `START 4000^` | `Unknown passport entry: SТАRТ 4000`; адреса не изменились |
| B | `ВХОД 4000^` в паспорте | Ошибки нет, но образ на диске побайтово равен варианту без `ВХОД` |
| C | `, ORG , 4000` в исходнике МАДЛЕН | `******ОШИБКА В КОП` |
| D | `, BASE, *` / `, BAS, *` | Это базирование коротких адресов (M8/M7), не адрес загрузки |
| E | `*MOSU A` | Меняет только печать адресов в листинге |

По исходникам `dispak/input.c:55`: `reg[INTRETREG] = psp.entry` —
`ВХОД`/`START` задают только адрес возврата/входа, а не базу загрузки.
В МАДЛЕН (`besm6-new/c-compiler/docs/Madlen.md`, §§15, 19.6) директив
`ORG`/`BASE`-для-загрузки нет: `BASE`/`BAS`/`REL`/`RELS` — механизм
базирования, `*MOSU` — только листинг.

Дополнительно: дамп памяти в момент входа в скомпилированную программу
(патч dispak, `--watch-pc=01000`, файл `core_at1000.bin`) показал код
только в `01000–01753₈` (модуль `PROGRAM`) и `04000–04025₈`. Остальные
49 модулей в этот момент в памяти отсутствуют — они подгружаются из
PERSO-библиотеки позже. То есть **не существует одного сплошного образа
всех 50 модулей в памяти dispak**, который можно было бы просто сдвинуть
на `+03000₈`. Кроме того, сдвиг не исправил бы абсолютные адреса в
командах `VTM`, которые загрузчик подставляет при загрузке.

## 5. Механизм РВС: `наз 04000` работает, но только с БЕМШ-объектами

Проверено на корректном объекте МАКРО-БЕМШ (`consul`, зона 430000 тома
2222). Задание (temp):

```
шифр 419999^
лен 67(2248)42(2113)^
лен 43(2222-зп)^
росп 0^
вход 1000^
е
в 1000
к 00 070 1003
к 00 070 1004
к 00 30 70000
с 0010 3400 0067 0105
с 0010 3500 0067 0106
в 2000
а1
мдл   consul430000^наз   04000^зонгп 430400 000001^
конец ^
_$
еконец
```

`dispak link_consul.b6` → `Р В С :01/78`, директива `наз 04000`
принята (РВС печатает разрешение внешних меток; неразрешённые ссылки
ожидаемы, т.к. остальные модули не подключены). То есть **механизм
задания базы 04000 в инструментарии есть** — это `наз 04000`.

Попытка скормить РВС МАДЛЕН-объект МРВ (PERSO-библиотека с базы 404000,
директивы `мдл PROGRAM434100^наз 04000^зонгп …`) дала:

```
Р В С :01/78
 ОШ.В ИНФ.СЛ.ЭКСТ
 70141  00 170 1706 *70
```

Перебор зон `434100/434101/434102/434103` не изменил результат.
Для сравнения, МАКРО-БЕМШ-модуль, скомпилированный в ту же temp-копию
2348, опознаётся как объект, но РВС сообщает `НЕТ TINYM В 430200` —
то есть диагностика различается; в любом случае готового пути
«МАДЛЕН → РВС с наз 04000» не получено.

## 6. Итог и рекомендация

1. Если `04000(8)` — **база PERSO-библиотеки на томе 2348**: рецепт §2–§3
   рабочий и проверен; `mrv_BASE4000.bin` готов к записи на рабочую копию.
2. Если `04000(8)` — **адрес загрузки МРВ в памяти**: dispak-компиляция
   МАДЛЕН его не поддерживает (§4). Нужен МАКРО-БЕМШ-вариант исходника
   МРВ или адаптация РВС под МАДЛЕН-объекты; без этого честно сообщаем,
   что задача не решена.
3. Паспорт МРВ из DIANA_BARS по-прежнему отсутствует
   (`docs/passport/MRV_PASSPORT.md`), поэтому длина записи зон и
   итоговая конфигурация не могут быть подтверждены из документов.
