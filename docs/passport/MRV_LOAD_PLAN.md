## 1. Главное уточнение: что такое `4000(8)` и куда писать

Документальные источники дают **три разных смысла числа 4000**, их нельзя
смешивать:

| Источник | Запись | Что это на самом деле |
|---|---|---|
| Паспорт PDF, стр.1 (`DIANA_BARS_PASSPORT.md:84-85`) | `BARS 01000`, `СВОБОД 04000`, `РВ C 02000` | **Адрес в памяти**: точка входа программы 01000₈, первая свободная ячейка после загрузки блока — 04000₈. Это НЕ номер зоны диска. |
| Рукописный паспорт, стр.2 (`...:136`) | `ВХОД 1 ∧ ОЗУ 3 ∧ ДИС 31(2048)` | `ВХО 1` — адрес входа; `ДИС 31(2048)` — логический номер 31 → том 2048. Системный том для задачи — **2048**, не 2348. |
| Листинг стр.1 | `FOR Z110 OF D204`, приписка `110-я зон D2048` | Готовая колода ДИАНА-БАРС физически лежит в **зоне 110₈ тома 2048** (проверено `besmtool view 2048 --start=72 --encoding=g`: там дословно `ТКН000ШИФР521018ЗС5‾ … EEВ1А3 … *NAME ДИАНА-БАРС …`). |

**Вывод (проверен на копиях):** писать объектный блок МРВ «в зону 4000
тома 2348» — технически возможно, но это **PERSO-библиотека по зоне
4000₈**, а не «блок, загруженный по адресу 4000₈». Адрес 04000 из паспорта
задаётся загрузчиком (результат компиляции), а не номером зоны диска.
Том 2348 в нашем сценарии — **рабочий том для задания/библиотеки**;
том 2048 — системный том, который объявлен в паспорте (`ДИС 31(2048)`).

## 2. Какой механизм записи требует dispak — результаты опытов

Проверено на копиях (exp2, exp3, exp5):

| Механизм | Команда/карта | Результат на копии | Пригодность для МРВ |
|---|---|---|---|
| **PERSO-библиотека** | `лен 40(2348-ЗП)^` + `*to perso:404000` | `ДЛИНА LIBRARY 013 ЗОН`, `КОНЕЦ ЗАДАЧИ`; каталог 50 модулей в зоне 4000₈; 11 зон 4000–4012₈ | ✅ **Рабочий путь.** МРВ — МАДЛЕН, `*assembler` собирает его и `*to perso` пишет каталог + тела модулей. |
| **ЗОНМОД** (сырой объект в зону) | `ЗОНМОД404000  0001^` в шапке `asm.pl` (`лент 40(2348-ЗП)^`) | `МОДУЛЬ ЗАПИСАН В ЗОНЫ С 404000 ПО 404000`, 0 ошибок | ⚠️ Работает, но только для **БЕМШ**-исходника (проверено на `TINYM СТАРТ 4000`). МАДЛЕН-текст `mrv_all.txt` в эту шапку не вставляется. |
| **ЗОНГП** | `НАЗ 0<имя>^` + `ЗОНГП43<зона>  00<len>^` (`asm.pl`, `rvs.src`) | Не прогонялся: это механизм сборки **модулей ОС** (ре-dispak, `лент 43(2222-ЗП)`), не запись пользовательской задачи МРВ | ❌ Не нужен для МРВ. |
| `*perso` (чтение) | `*perso:404000`, `*perso:63160,cont` | `LIBRARY FROM …`, загрузка PROGRAM 01000 | ✅ Используется на phase 2. |

Дополнительно проверено:
- `шифр 521018 зс5^` принимается dispak; ключ **`зс5` обязателен** —
  без него `eeв1а3` даёт `МАССИВ ПУСТ`.
- `вход 1^` и `дис 31(2048)^` в паспорте принимаются и **не меняют**
  записанный образ (md5 диска совпадает с вариантом без них).
- Карта `тел` (ТЕЛЕ) подавляет печать на АЦПУ (в логе остаётся 5 строк),
  но запись на диск всё равно происходит.
- Строка `е в1` из рукописного паспорта **недопустима** для dispak:
  `ЧУЖОЙ СИМВОЛ`, НПК 8. `Е` должна быть отдельной картой.

## 3. Проверенный сценарий на копиях (две фазы)

### Фаза 0 — компиляция

```bash
cd /tmp/.private/azizz/opencode/glissada/write2348
bash /home/azizz/Yandex.Disk/re-mrv/scripts/build_one.sh \
  /home/azizz/Yandex.Disk/re-mrv/docs/integration/mrv_all.txt MRVALL $PWD/build
grep -v '^\*no list$' build/mrv_all.b6 > build/mrv_all_full.b6

## 4. Что НЕ проверено / требует реального диска или подтверждения

1. **Тома 2074 и 2075.** В арсенале только 2048, 2053, 2099, 2113,
   2148, 2153, 2222, 2248, 2348; подлинных 2074/2075 нет. В опыте
   они созданы как копии 2248. Из-за этого:
   - `*TAPES:671201` подлинной колоды даёт `НЕДОПУСТИМЫЙ СДВИГ`
     (НПК 25) — строка удалена;
   - `ИСПОРЧЕН КАТАЛОГ БИБЛИОТЕКИ 67`.
   Для подлинного запуска нужны настоящие тома 2075 (ленты) и 2074
   (PERSO 63160) либо явное указание оператора, какой том использовать
   вместо них.
2. **ВХО 1 из паспорта.** dispak принимает `вход 1^`, но в наших
   колодах он не влияет на загрузку (загрузчик всё равно ставит
   PROGRAM 01000). Смысл `ВХО 1` в подлинной машине (возможно,
   адрес 1 как точка входа диспетчера) EXPERIMENTAL НЕ подтверждён.
   Рукописная форма `е в1` dispak отвергает.
3. **К-карты и С-карта паспорта** (`К00 070 0010`,
   `К01 24 02000 00 042 0001`, `К00 050 7701`, `К00 074 0000`,
   `С0010 0100 0031 0110`) в наших колодах **не использовались** —
   их содержимое и назначение не расшифровано; переносить их в .b6
   без понимания нельзя.
4. **Fortran DEB** (`docs/deb/deb_fortran_src.txt`) собирается
   отдельно через `*system` и в `mrv_all.txt` не входит; в блок не
   добавлен.
5. **Незакрытые символы** (`PRINT1…12`, `SPIGUN`, `DERD`, `DEWR`,
   `RZAVAR`, `RQTOCMD` и др.) — свойство текущего 50-модульного
   набора; устранение требует отдельной работы, к записи на диск
   отношения не имеет.
6. **Запись на реальный диск не выполнялась.** Перед ней
   обязательны: резервная копия тома, проверка, что зона 4000₈
   тома 2348 свободна (сейчас на копии она пуста), и явное указание
   оператора — писать на 2348 или на 2048/2074.

## 5. Итоговая рекомендация

1. Если цель — **получить работающий блок МРВ на диске 2348**:
   фаза 0 + фаза 1а (`*to perso:404000`), проверка `besmtool view`.
   Это проверено на копии, md5-evidence есть.
2. Если цель — **воспроизвести паспорт ДИАНА-БАРС**:
   фаза 0 + фаза 1б (`*to perso:63160` на том 2074) + фаза 2.
   Прогон на копиях доходит до `КОНЕЦ ЗАДАЧИ` с PROGRAM 01000,
   DOG 02000; для точного повтора нужны подлинные 2074/2075.
3. `ЗОНМОД` и `ЗОНГП` — механизмы сборки модулей ОС/БЕМШ; для
   МАДЛЕН-текста МРВ они не применимы без перевода исходника в БЕМШ.
