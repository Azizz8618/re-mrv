### 2.3 Что понимается под «4000» — важные различия

В re-glissade **нет ни одного упоминания «зона 4000(8)»** ни в рабочем дереве файлов,
ни в сообщениях коммитов. Проверено:

- `git log --all -S'4000(8)'` — 0 совпадений;
- `git log --all -S'зона 4000'` — 0 совпадений;
- `git grep '404000'` по всем коммитам даёт только машинные слова в
  дампах/трассах (`RUNS/.../*.err`, `docs/analysis/glis1r-a4-dump.log`),
  а не карты `*perso:404000`.

Найденные «4000» имеют другой смысл:

| Где | Смысл | Не путать с зоной диска |
|---|---|---|
| `docs/analysis/p19-PERSO-link-eksperiment.md:76-77`, `p20-proekt-linker.md:11` | sym-элемент `(0o4000+X)<<24 | C<<12 | D`, `C=0o6700` — вход PERSO | Это кодировка записи линкера, не номер зоны 2348 |
| `docs/analysis/glis1r-a4-dump.log`, `TOOLS/exp_w_masks.py:18`, `RUNS/run-2026-11-12/ANALIZ.md:234` | восьмеричные слова/маски `0o4000…`, «зона 4 = печать» (барабан/спул) | Не PERSO-зона диска |
| `/home/azizz/Yandex.Disk/re-mrv/docs/2053_passports.txt:3,4,16-18` | `ВХО 4000`, `ЕВ4000` — **начальный адрес задачи 4000(8)** в паспортах диска 2053 | Это вход, а не зона 4000 тома 2348 |

Проверка текущего образа (только чтение):
`BESM6_PATH=$HOME/.besm6 /home/azizz/Yandex.Disk/dispak/build/besmtool/besmtool view 2348 --start=2048 --last=2048 --encoding=t`
вывела только пустую строку и `*`; `besmtool list 2348` сообщает

не содержит видимого каталога; в re-glissade нет свидетельств её
использования. Это **не доказательство** того, что зона свободна или зарезервирована —
нужна отдельная проверка владельца диска.

## 5. Итог и пробелы

1. re-glissade **не содержит** готового паспорта/задания под зону 4000(8)
   тома 2348 и не содержит МРВ. Это проект «Глиссада-6»; его вклад —
   проверенная механика записи PERSO-зон на 2348 и OSINT по К-71/СМ-2.
2. Ближайший готовый сценарий — `sh TOOLS/install-2348.sh 1` для зоны
   2700(8). Перенос на 4000(8) делается через параметр
   `TOOLS/build-dialog.py <work> 4000` и замену чисел в `install-2348.sh`.
3. Для самой программы МРВ нужно использовать цепочку `re-mrv` +
   `re-dispak/testdks/build_madlen.sh`; re-glissade даёт только обвязку
   записи/проверки и pty-запуск.
4. Пробелы (GAP): нет готового паспорта задачи для МРВ с зоной 4000(8);
   нет сведений о том, что зона 4000(8) тома 2348 предварительно
   очищена/отведена; нет эмулятора СМ-2 (только план порта `hp2100`);
   команда запуска МРВ с диска в re-glissade отсутствует.
5. Терминологическая ловушка: `ВХО 4000` в паспортах 2053, `0o4000` в
   sym-элементах и «зона 4 = печать» в логах — **не** зона 4000(8) диска 2348.
