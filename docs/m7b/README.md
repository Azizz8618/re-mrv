# M7B — модули преобразования чисел БЭСМ-6 ↔ M7000

Источник: `СПО_тексты.pdf`, файловые стр. **217–223** (шапки «АВТОКОД MADLEN / (1.10.72)»,
дата 28.04.86). OCR `ocr/p217.txt … p223.txt` использовался **только как индекс**;
вся транскрипция выполнена по изображениям, отрендеренным в PNG 280 dpi
(`/tmp/.private/azizz/opencode/glissada/m7b/png/`).

## Состав

На стр. 217–223 находятся **четыре независимые подпрограммы** (каждая со своим
`NAME`, `BLOCK,BASE,B,M` и `END`, statistical block «СТРУКТУРА ПОДПРОГРАММЫ»,
`ЧИСЛО ОШИБ. ОПЕРАТОРОВ 0000`):

| Стр. | Метки листинга | Имя | Назначение (по шапке листинга) |
|------|----------------|-----|--------------------------------|
| 217–218 | M7B00060…M7B00930 | `RMTOB` | ПЕРЕВОД ВЕЩЕСТВЕННОГО ЧИСЛА M7000 В ПРЕДСТАВЛЕНИЕ БЭСМ-6; `CALL RMTOB(B,M)` |
| 219 | M7B00940…M7B01200 | `IMTOB` | ПЕРЕВОД ЦЕЛОГО ЧИСЛА M7000 В ПРЕДСТАВЛЕНИЕ БЭСМ-6; `CALL IMTOB(B,M)` |
| 220–221 | M7B01210…M7B01750 | `RBTOM` | ПЕРЕВОД ВЕЩЕСТВЕННОГО ЧИСЛА БЭСМ-6 В ПРЕДСТАВЛЕНИЕ M7000; `CALL RBTOM(B,M)` |
| 222–223 | M7B01760…M7B02270 | `IBTOM` | ПЕРЕВОД ЧИСЛА БЭСМ-6 В ЦЕЛОЕ ПРЕДСТАВЛЕНИЕ M7000; `CALL IBTOM(B,M)` |

Сохранены все константы и таблицы: `=14`, `=377`, `=100`, `=17 7400`,
`=37 7777 7740 0000`, `=R1.E19`, `=4000 0000 0007 7777`, `=10037 7777 7770`,
`=10`, `=37 7776 0000 0000`, `=1774`, `=376`, `=200`, `=7 7777`,
`=20 0000 0007 7777`, `17 7777 7770 0000`; тексты `GOST,6…`, `GOST,16…`,
`CONT,14…` (сообщение «СЛИШКОМ БОЛЬШОЕ ЧИСЛО В …'172'»); `LOG`, `BSS`,
`Z00`, `*64`, `RSS`(→`BSS`), `PNFJT`.

## Файлы

**docs/m7b/**
- `m7b_src_raw.txt` — дословная транскрипция по изображениям (до правок).
- `m7b_src.txt` — итоговый компилируемый исходник (все 4 подпрограммы).
- `m7b_run.txt` — тестовая копия: добавлена строка `PROGRAM : , ENTRY,` после первого `NAME`.
- `m7b_{rmtob,imtob,rbtom,ibtom}_fix.txt` — те же 4 модуля по отдельности (так они

**build/m7b/**
- `*.b6` — обёртки для dispak (`build_madlen.sh`), `*_compile.log` — протоколы трансляции
  (logs are the `.lst` of these runs; dispak создаёт их с `*no list`).

## Правки (только синтаксис / очевидные описки)

| # | Было (в скане/транскрипции) | Стало | Причина |
|---|-----------------------------|-------|---------|
| 1 | каждая строка без ведущего пробела | один ведущий пробел | без poz.1 ассемблер выдаёт «ОТСУТСТВУЕТ ЗАГОЛОВОК ПОДПРОГРАММЫ»; `С`-комментарии, наоборот, оставлены строго в поз.0 |
| 2 | `BAS:BASE,BASE,BAS` | `BAS : , EQU ,BASE` | «ОШИБКА В МОДИФИКАТОРЕ»; по таблице ссылок оригинала BAS = BASE = 00000 |
| 3 | `UTA` | `YTA` | в таблице мнемоник ассемблера (`besm6-new/dubna/assembler.cpp`) есть `yta`, нет `uta`; в типовом шрифте Y/U неразличимы |
| 4 | `R_BITS` | `R BITS` | `_` недопустим в идентификаторе; в листинге напечатано «R BITS» с пробелом |
| 5 | `BIG P : , RSS ,` | `BIG P : , BSS ,` | `RSS` не поддерживается ассемблером dispak |
| 6 | `=100 P` | `=100` | суффикс `P` даёт «ОШИБКА В АДРЕСЕ» |
| 7 | `: , UTA` / `: , ITA` (без запятой) | `: , YTA ,` / `: , ITA ,` | ассемблер требует запятую после opcode без операнда |
| 8 | `EXIT : , B, STX ,` | `EXIT : B, STX ,` | запятая после `:` перед символическим префиксом `B` не принимается (префикс сохранён) |
| 9 | `PRINT : , 700 ,TEXT` | `PRINT : , Z00 ,TEXT` | `700` — неизвестный opcode; `Z00` — директива текстового вывода, применённая в 4-м модуле |
| 10 | `PNFJT` не описан | добавлено `PNFJT : , BSS , 1` | внешний символ оригинального комплекса (`*64 ,PNFJT`); для самостоятельной сборки нужно определение |
| 11 | строка `8,` (M7B02200, префикс без операции) | удалена | «НЕДОПУСТИМЫЙ ОПЕРАТОР» |
| 12 | — | добавлены 4 заголовочные `С`-строки (Programms / … И ОБРАТНО) | сохранение шапки оригинала в `m7b_src.txt` |

## Результат

- Каждый из 4 модулей компилируется отдельно через
  `/home/azizz/Yandex.Disk/re-dispak/testdks/build_madlen.sh` → **0 ошибок**
  (`Трансляция без ошибок`); в оригинальных листингах тоже `0000`.
- Сводный `m7b_src.txt` → **0 ошибок**.
- `m7b_run.txt` → **0 ошибок**, программа выполнена до конца:
  `RМТОВ 01000`, `PROGRAM E 01000`, `КОНЕЦ ЗАДАЧИ`, `00411: 00 074 0000 *74`.
  Вывода на АЦПУ нет — подпрограммы преобразования печатают только сообщение
  об ошибке переполнения (`СЛИШКОМ БОЛЬШОЕ ЧИСЛО …`); при обычном завершении
  вывод не предусмотрен.

## Честно о неопределённостях

- Точное прочтение констант `=R1.E19` (M7B00750), `=10037 7777 7770` (M7B01140),
  `=376` (M7B01540) и префикс `Н` в строках `GOST,6Н…` / `GOST,16Н…` сохранены
  «как напечатано»; семантика не проверялась (недостаточно данных в листинге).
- Поведение `RMTOB/IMTOB/RBTOM/IBTOM` при ненулевых входных значениях не тестировалось:
  для этого нужен вызывающий модуль с передачей параметров `B,M` по соглашению
  `BLOCK,BASE,B,M`; в доступных текстах такое соглашение не описано.
- Имена модулей прочитаны как `RMTOB / IMTOB / RBTOM / IBTOM` (в шрифте `O` и `0`
  неразличимы); это реконструкция по соглашению R/I + M/B + TO + M/B,
  подтверждённая шапками «ПЕРЕВОД … M7000 В … БЭСМ-6» и наоборот.
