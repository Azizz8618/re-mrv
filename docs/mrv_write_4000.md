# Задание на компиляцию блока МРВ с адресом 4000(8) и запись на том 2348 — черновик

Дата: 18.11.2026. Исполнитель: сабагент.
Режим: **только temp-копии**. Ни один реальный диск не изменялся (проверка md5 — раздел 7).

## 1. Постановка и принятое прочтение

Запрос: подготовить задание, которое компилирует весь блок МРВ с начальным
адресом записи `4000(8)` и записывает его на рабочий диск `2348`.

Уточнение пользователя (дословно):
> `4000(8)` — адрес начала записи всего блока МРВ (это НЕ номер зоны диска).

Ориентиры, выданные пользователем: `re-siprod/drakon/asmjob.py`
(`вход 4000`, `в 4000`, `к 15 24 04000`, `ЗОНМОД...`),
`re-siprod/tools/record2348_new.py`, `re-siprod/pascal/scripts/запись-2348.sh`,
`re-siprod/notes/madlen-object.md`, `re-siprod/notes/loader.md`.
Механику re-glissade `*perso:404000` пользователь ранее запретил; здесь она
**не применяется как готовое решение**, а используется только как один из
двух возможных прочтений числа 4000 (раздел 4).

Исходники: `docs/integration/mrv_all.txt` (8281 строка, 50 модулей, МАДЛЕН
1.10.72), `docs/deb/deb_fortran_src.txt` (Fortran, `*system`, собирается
отдельно). Образ тома: `/home/azizz/Рабочий стол/БЭСМ-6/2348`.

### 2.1 Исходный блок МРВ компилируется без ошибок

```bash
cd /home/azizz/Yandex.Disk/re-mrv
bash scripts/build_one.sh docs/integration/mrv_all.txt MRVALL build/integration

Результат (уже был в репозитории, подтверждено повторно): 50 блоков с

### 2.2 Путь dispak + `*assembler` НЕ умеет задавать базу 4000(8)

Проверено тремя независимыми опытами:

| Опыт | Что делалось | Результат |
|------|--------------|-----------|
| A | В паспорт `.b6` добавлена строка `START 4000^` | `Unknown passport entry: START 4000`; адреса не изменились (`PROGRAM 01000`) |
| B | В паспорт добавлена строка `ВХОД 4000^` (ключевое слово из `vsinput.c:248-256`) | Ошибки нет, но образ записанного на диск tom-файла **побайтово равен** варианту A (`cmp -l` → 0 различий) |
| C | В исходник добавлена директива `, ORG , 4000` | `******ОШИБКА В КОП` — МАДЛЕН не знает такой директивы |

Список допустимых директив МАДЛЕН (по `re-siprod/notes/madlen-stars.md`,
раздел 6, и по разбору исходников): `NAME`, `END`, `BSS`, `EQU`, `LC`,
`ISO`, `SUBP`, `LOG`, `ENTRY` и т.п. Директивы `ORG`/`START`/`BASE` в них
**нет**. Следовательно, «аналога `СТАРТ`/`ORG`» для МАДЛЕН-текста МРВ в
dispak не существует; `START`/`ВХОД` задают только точку входа задачи
(`reg[INTRETREG] = psp.entry`, `dispak/input.c:55`), а не базу загрузки
модулей.

Артефакты: `exp_base.lst`, `exp_start4000.lst`, `mod_start4000.bin`,
`mod_start0.bin`, `t_org.lst`, `t_plain.lst`.

### 2.3 МАКРО-БЕМШ-колода SIPROD (`asmjob.py`) — что в ней на самом деле

Дословно (`re-siprod/drakon/asmjob.py:20-24`):

```
шифр 419999^ / трак 64^ / лент 30(2048-6200)^ / лент 42(2099)^ /
лент 27(2248-ЗП)^ / ацп 40^ / росп 0^ / врем 240^ / лист 0-37^ /
вход 4000^ / е / в 4000 / к 00 010 4003 / к 15 24 04000 /
к 00 066 0001 00 000 0100 / с 3000 67 / в 14000 / а1 / ВВД$$$
```

Оценка этой колоды в `re-siprod/docs`-аналоге — `re-mrv/docs/siprod_zone4000.md`
§2.1: `вход 4000` — **адрес входа в диспетчерский блок задания, а не зона
диска**; это стандартная шапка трансляторного задания МАКРО-БЕМШ.

Проверено в temp (минимальный модуль `TINYM СТАРТ 4000`):

1. **`лент 27(2248-ЗП)` в этом dispak не работает**: `ЧУЖОЙ СИМВОЛ`, НПК 5.
   Причина — `dispak/vsinput.c:338-341` требует восьмеричный номер ленты
   `030 ≤ u < 070`; `27` читается как 23(10) и отвергается. Рабочий вариант —
   `лент 40(2248-ЗП)`. С `лент 40` трансляция проходит:
   `ЧИСЛО ОШИБОК=0000`, `МОДУЛЬ ЗАПИСАН В ЗОНЫ С 402720 ПО 402720`.
2. Изменение `СТАРТ 4000 → СТАРТ 0` в исходнике **и** изменение
   `к 15 24 04000 → к 15 24 05000` в колоде дали **побайтово одинаковый**
   объект на temp-диске 2248 (`cmp -l` → 0). То есть утверждение
   «`к 15 24 04000` задаёт базу записи скомпилированного блока» нашими
   опытами **не подтверждено**. Не исключено, что база объекту приписывается
   позже — при связывании/загрузке (директива РВС `наз`, см.
   `re-siprod/notes/linker.md:99`, `:116-117`), — но это требует отдельной
   проверки с реальным линкером и паспортом.

Артефакты: `tiny.be`, `tiny_job40.b6`, `tiny_job40.lst`, `fa/2248`, `fb/2248`,
`freshA/2248`, `freshB/2248`.

### 2.4 Число 4000(8) на диске 2053

`docs/2053_passports.txt` содержит паспорта с `ВХО 4000` / `ЕВ4000`:

- строка 3: `ДИС 35(2048)^ВРЕ 943^ВХО 4000^…Б:-DМS-`
- строка 4: `ДИС 60(2048)^…ВХО 4000^ЕВ4000…Б:=NDМS`
- строки 16–18: `ВХО 4000^ЛИС 0-25,32^…ЕВ4000…БИАЭNЕW / БИАЭОLD / Б МС*81`

`ВХО`/`ЕВ` — **начальный адрес задачи в памяти**, ещё одно подтверждение,
что 4000(8) в диспак-контексте — адрес, а не номер зоны.
Паспорта `МРВ`/`DOG` на дисках не найдены (`docs/passport/MRV_PASSPORT.md`).
В `docs/siprod_zone4000.md` §1 прямо сказано: готового сценария «записать МРВ
в зону 4000 тома 2348» в re-siprod нет.

### 2.5 Черновик A: полный МРВ → 2348, зона 4000(8), проверка в temp

Файл: `DRAFT_A_madlen_vhod4000.b6` (`.b6` от `build_one.sh` + две добавленные
строки паспорта/ленты и одна карта записи):

```
шифр 419999 зс5^
лен 41(2048)^
лен 40(2348-ЗП)^          <- том 2348 на запись (в temp-копии)
ВХОД 4000^                <- адрес входа (принято dispak)
eeв1а3
*name MRVALL
*no list
*assembler
<8281 строка docs/integration/mrv_all.txt>
*to perso:404000          <- карта записи в зону 4000(8) тома 2348
*end file
``````
еконец
```

Прогон в temp:

```bash
cd /tmp/.private/azizz/opencode/glissada/mrv_write
mkdir -p finaldisk && cp /usr/local/share/besm6/{2048,2053,2099,2348} finaldisk/
BESM6_PATH=$PWD/finaldisk dispak DRAFT_A_madlen_vhod4000.b6 > DRAFT_A_compile.lst 2>&1
```

Результат: `ДЛИНА LIBRARY 013 ЗОН`, `КОНЕЦ ЗАДАЧИ`. Полный листинг без
`*no list` (`DRAFT_A_full.lst`) содержит **50** строк
`ЧИСЛО ОШИБ. ОПЕРАТОРОВ 0000` — все модули МРВ оттранслированы чисто.
Контроль записанной зоны:

```bash
BESM6_PATH=$PWD/finaldisk besmtool view 2348 --start=04000 --last=04000 --encoding=t
```

В зоне `4000.0000` виден каталог со всеми модулями МРВ: `BASOR, FINAL, DESW,
GOTO, MEM, TOSTK, SHISO, TODE, JOCTI, GIVRGM, GIVRGS, RDM35, USM35, NDRS1,
СБОР1…4, ONE, TWO, FLS1, IBTOM, RBTOM, IMTOM, RMTOM, TABLO, W16COD, REAL,
УСТ, W48COD, INT, R16COD, R48COD, RDTAB, RSTREG, RREAL, BITTON, BITTAS,
NTABIT, DATA, ROTOCMD, T TOCMD, WRITED, RUFCOM, LINEIN, LINEOUT, RQTOCM,
WRITE, READ, PROMON, DOG, PROGRAM, NEWDOG`.

**Важная оговорка:** `*to perso:404000` пишет **библиотеку PERSO** (каталог +
тела модулей), а не «непрерывный блок, загруженный по адресу 4000(8)».
Адреса `PROGRAM 01000`, `DOG 02000` внутри модулей при этой записи
**не сдвинулись** — проверено (`cmp` вариантов с `START` и `ВХОД` = 0).

## 3. Что осталось НЕ установленным (без домысливания)

1. **Смысл `4000(8)` расходится с карточкам.** Уточнение пользователя говорит,
   что это адрес начала записи, а не номер зоны. Однако:
   - в `re-glissade` (`docs/re_glissade_findings.md` §2.3) тот же самый
     `4000(8)` отображался как зона: `besmtool --start=2048` (дес.) и карта
     `*perso:404000`;
   - в `docs/2053_passports.txt` `ВХО 4000` — адрес входа в памяти.
   Черновик A реализует ** PERSO-зону 4000(8)**; если пользователь имеет в виду
   **базу загрузки в памяти 4000(8)**, черновик A её не обеспечивает.
2. **Паспорт МРВ из DIANA_BARS отсутствует** (`docs/passport/MRV_PASSPORT.md`).
   Без него неизвестны:
   - требуемая зона/адрес на томе 2348 и длина записи в зонах (для `ЗОНМОД`
     или `зонгп`);
   - поля паспорта (`ВРЕ`, `ОЗУ`, `ТРА`, `ЛИС`, `АЦП`, `ФИЗ`, `СПЕ`, `АВО`,
     `ИНК`, `ТЕЛ`);
   - требуемый комплект модулей (Fortran `DEB` собирается отдельно через
     `*system` и в `mrv_all.txt` **не входит**);
   - кто именно из паспортов `2053` с `ВХО 4000` (`ЗС5`, `ЗС6`, `ЗС7`,
     `ЗСU`, `ЗС:`) относится к МРВ — совпадения по имени не найдено.
3. **Как задать базу 4000(8) объекту МРВ.** Единственный описанный в
   re-siprod механизм — РВС `наз 04000` + `зонгп 43<зона>`
   (`notes/linker.md:99,116-120`), но он требует объектные модули в зоне
   ПЕРСО и не проверен на нашем 50-модульном наборе.
4. **МАКРО-БЕМШ-исходника МРВ нет.** `mrv_all.txt` — МАДЛЕН; колода
   `asmjob.py` ожидает БЕМШ (`СТАРТ`, `СЧИМ`, `ПБ`, …). Прямая подстановка
   `mrv_all.txt` в неё невозможна; конвертация не выполнялась.

## 5. Дословные команды воспроизведения (только temp!)

```bash
# 1) Рабочая область
mkdir -p /tmp/.private/azizz/opencode/glissada/mrv_write
cd /tmp/.private/azizz/opencode/glissada/mrv_write
mkdir -p finaldisk
cp /usr/local/share/besm6/{2048,2053,2099,2348} finaldisk/

# 2) Компиляция всего блока МРВ + запись в temp-копию тома 2348
BESM6_PATH=$PWD/finaldisk dispak DRAFT_A_madlen_vhod4000.b6 \
    > DRAFT_A_compile.lst 2>&1

# 3) Полный листинг (50 x "ЧИСЛО ОШИБ. ОПЕРАТОРОВ 0000")
grep -v '^\*no list$' DRAFT_A_madlen_vhod4000.b6 > DRAFT_A_full.b6
BESM6_PATH=$PWD/finaldisk dispak DRAFT_A_full.b6 > DRAFT_A_full.lst 2>&1
grep -cE 'ЧИСЛО ОШИБ\. ОПЕРАТОРОВ +0000' DRAFT_A_full.lst   # -> 50

# 4) Контроль записанной зоны 4000(8)
BESM6_PATH=$PWD/finaldisk besmtool view 2348 \
    --start=04000 --last=04000 --encoding=t

# 5) НИ В КОЕМ СЛУЧАЕ не запускать п.2 с BESM6_PATH, ведущим
#    в ~/.besm6, /usr/local/share/besm6 или "Рабочий стол/БЭСМ-6".
```

## 8. Рекомендация

1. Дождаться паспорта МРВ из DIANA_BARS (или прямого указания оператора),
   который даст: зону/адрес на 2348, длину, поля паспорта и список модулей.
2. Если окажется, что `4000(8)` — **база загрузки в памяти**, принципиально
   пригоден только путь РВС с `наз 04000` (требует объектные модули в ПЕРСО
   и отдельной проверки); черновик A в этом случае не подходит.
3. Если `4000(8)` — **зона тома 2348**, черновик A уже проверен в temp и
   может быть применён к рабочей копии тома после замены `BESM6_PATH`.
